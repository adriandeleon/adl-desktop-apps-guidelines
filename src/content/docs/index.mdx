## Where to start

There are two ways to implement Pauta. A new app starts from
[adl-desktop-app-template](https://github.com/adriandeleon/adl-desktop-app-template), a GitHub template repository: a small
runnable app with its tests, CI and release workflows and every repository document, built to the edition its README
names. Click **Use this template**, run `scripts/rename.sh <AppName> <package>`, then add any rule from a later
edition. An existing app works through the [New app checklist](checklist/) and its own list under
[Gaps per app](family/gaps/).

## How to read it

<div class="levels-legend">
  <p><span class="lvl lvl-must">MUST</span> A release blocker for a new app.</p>
  <p><span class="lvl lvl-should">SHOULD</span> Expected unless the app has a stated reason.</p>
  <p><span class="lvl lvl-may">MAY</span> A pattern worth copying when the app grows into it.</p>
</div>

Every rule has a permanent ID, such as `KBD-07`, that links to the rule itself and is never reused. Under the rule,
*Check* says how to verify it in an app: by reading the code, by a named test, or by hand in the running app.
*Reference* names where Editora, or another app, does it. An app cites a rule by its ID and the edition it meets, and
anyone, person or coding agent, can audit it rule by rule. For coding agents, every edition serves
<a href={`${import.meta.env.BASE_URL.replace(/\/?$/, "/")}llms.txt`}>llms.txt</a>, how to use these rules, and every
rule in one file as <a href={`${import.meta.env.BASE_URL.replace(/\/?$/, "/")}llms-full.txt`}>Markdown</a> or
<a href={`${import.meta.env.BASE_URL.replace(/\/?$/, "/")}rules.json`}>JSON</a>.
[Coding agents and LLMs](coding-agents/) explains them, and how to have an agent build to the rules or audit an
app against them.

When this guide and Editora disagree, check Editora's code, then fix whichever is wrong.

The MUSTs each app still misses, then the SHOULDs open in several apps. Every row was read against an audit of the
app's MUSTs on 2026-11-10, at the head of the app's default branch that day, and Editora's against the rules that cite
it. A part an app lacks is listed once, under the rule that requires it, and the rules about how that part behaves
follow as links on the same clause: a missing find bar is [FIND-01](../../templates/find-bar/#find-01)'s, and
[FIND-02](../../templates/find-bar/#find-02), [FIND-06](../../templates/find-bar/#find-06) and
[FIND-07](../../templates/find-bar/#find-07) follow it. Five rules say in their References that no app has been read
through for them yet ([OS-04](../../same-on-every-os/#os-04), [PERF-01](../../performance/#perf-01),
[PERF-02](../../performance/#perf-02), [PERF-03](../../performance/#perf-03),
[PERF-08](../../performance/#perf-08)): a row holds what was found so far, and a row with no clause for one of them
is not a pass. A command id, catalog key, chord, command-line flag, environment variable, property in `pom.xml` or
`pauta.json`, or file the repository must carry that a rule's statement names is required as spelled; a class,
method, style class, branch or workflow file there is Editora's, and an app's equivalent meets the rule
([Coding agents](../../coding-agents/#what-a-rule-looks-like)).

## Missing MUSTs

Six MUSTs are open across the family. The rows leave OS-02, WIN-11, WIN-12 and ACC-01 out, and say for MENU-16 and
CLI-12 what each app lacks. No app has the one `Os` class that alone reads `os.name`
([OS-02](../../same-on-every-os/#os-02)): 51 files read it in Editora, 20 in Termina, 19 in Torrenta, 15 in Mirada, 4
in nux and 3 in Modula, and eight more of Editora's tell Windows apart by `File.separatorChar` or
`File.pathSeparatorChar` instead. No app fixes the order of a dialog's buttons ([WIN-11](../../window-shell/#win-11)):
none calls `setButtonOrder`, so Editora, Torrenta, Termina, Mirada and nux draw theirs in JavaFX's order for the OS,
and Modula's one dialog has a single button. No app has a UI zoom ([WIN-12](../../window-shell/#win-12)): Editora,
Termina and Mirada zoom their content only (the text, the terminal's font, the image), and Torrenta, Modula and nux
have no zoom. So no app's menus follow one either ([MENU-16](../../menus/#menu-16)): Editora's and Mirada's, the two
that set the font on `.context-menu`, write 14 px as a fixed size. And no app meets all of
[CLI-12](../../command-line/#cli-12). And no app has the test that sweeps every window for a control with no name
([ACC-01](../../accessibility/#acc-01)): Termina's sweeps icon-only buttons, Editora's and Mirada's each check a few
named sets of buttons, and Torrenta, Modula and nux have none. Editora's in-window menu rows carry no accessible text;
Torrenta sets one in a single helper, which names every button of its main toolbar and the Search view's Clear button
and not its "···" button, and Modula sets none. The app template, which is not one of the six, meets all six
MUSTs: each rule's Reference says where.

## SHOULDs open in several apps

- **Windows `.msi` signing** ([REL-17](../../release/#rel-17)): no app signs its MSI yet; the certificate isn't
  chosen.
- **Settings in the macOS application menu** ([WIN-15](../../window-shell/#win-15)): only Mirada puts it there, with a
  key equivalent of its own where the rule asks for the active keymap's chord in the row's title. Editora, Termina,
  Torrenta, Modula and nux have no such row.
- **Maven's repository cached by every `setup-java` step** ([REL-25](../../release/#rel-25)): Editora, Termina and
  Torrenta each have a step without `cache: maven`.
- **The same short flags** ([CLI-13](../../command-line/#cli-13)): Termina and Torrenta take `-h`, `-v` and `-V`.
  Editora has no `-v` and Mirada no short flags; Modula reads no arguments, and nux reads two long flags of its own,
  `--minimized` and `--screenshot`, and no short one.
- **One tooltip delay** ([TBAR-14](../../toolbars-and-tooltips/#tbar-14)): no app sets 400 ms on every tooltip.
  Termina sets it on its icon buttons and leaves its palette's at JavaFX's second; Editora sets 300 to 400 ms on a
  few, Mirada 250 ms on one, and the rest set none.
- **The find command finding the next match, and every match painted** ([FIND-04](../../templates/find-bar/#find-04),
  [FIND-05](../../templates/find-bar/#find-05)): Editora's terminal find bar refocuses its field and its console
  bar has no command; Termina's refocuses too. A Debug Log drawn in a `TextArea` shows one match at a time.
- **Page Up and Page Down in the palette** ([PAL-06](../../templates/command-palette/#pal-06)): Torrenta's, Modula's
  and nux's palettes have neither.
- **The config read begun before the toolkit** ([PERF-16](../../performance/#perf-16)): Editora starts it in `main`
  and `start()` takes the result. Torrenta, Modula and nux load their settings inside `start()`, Torrenta and nux
  after their `main` has read the file once on the main thread; Termina reads them in `init()`, after the toolkit is
  up; Mirada's earlier read only happens in its native image.
- **A pinned toolbar tail** ([TBAR-15](../../toolbars-and-tooltips/#tbar-15)): Torrenta keeps Simple mode and Settings
  inside its `ToolBar`, so a narrow window overflows them before its icons.
- **Toolbar buttons that follow their command** ([TBAR-17](../../toolbars-and-tooltips/#tbar-17)): the buttons Editora
  adds from its catalog (Commit, Problems and the rest) stay enabled when their command can't act.
- **A stripe button's tooltip that follows its tool window's title**
  ([TBAR-12](../../toolbars-and-tooltips/#tbar-12)): Editora rebuilds the tooltip on a keymap switch only, so a title
  change (the Project window becoming "Current Folder") reaches the button's accessible text and the bottom stripe's
  label, not its tooltip.
- **Settings Sync** ([SYNC-01](../../templates/settings-sync/#sync-01)): Modula, Mirada and nux don't have it.
- **Copy in the Message Log on the keymap's copy chord** ([MLOG-04](../../templates/message-log/#mlog-04)): Editora's,
  Torrenta's, Termina's and Mirada's each copy on the platform's fixed chord alone. The template's does too, and none
  of its keymaps binds a copy command, so it has no second chord to read.
- **A tab's Git status in its tooltip** ([TABS-08](../../tabs-and-panels/#tabs-08)): Editora, the one app whose tabs
  hold files, shows the status by the title's color alone; its tab tooltip is the file's path.
- **The Message Log as an in-scene card** ([MLOG-08](../../templates/message-log/#mlog-08)): Termina's is a separate
  window keeping 500 entries, and Torrenta's card is 640 × 300, not 773 × 336.
- **The Help menu's rows in one order** ([DOCS-07](../../documentation/#docs-07)): Mirada's Help submenu holds Message
  Log, Debug Log, Report a Problem, then Check for Updates, with its Command Palette, Documentation, keyboard
  reference and About rows beside it in the main menu. Editora's Welcome Page row is in its View menu, and so is
  Termina's Command Palette row.
- **A keyboard reference in the Help menu** ([DOCS-08](../../documentation/#docs-08)): Editora's keybinding editor is
  a page of Settings that no Help row opens, and Mirada's keyboard-reference row sits beside its Help submenu.
- **A help chord in the palette** ([PAL-08](../../templates/command-palette/#pal-08)): only Editora's palette opens
  the selected command's page in the docs. Termina's, Torrenta's, Mirada's, Modula's and nux's have no such chord.
- **AWT headless unless a listed use needs it** ([CLI-09](../../command-line/#cli-09)): Modula's and nux's `main`
  never set `java.awt.headless`, so AWT is headful on every OS, Linux included.
- **Screenshots rendered at 2×** ([DOCS-18](../../documentation/#docs-18)): Termina's, Torrenta's and nux's capture
  hooks write the scene at its own size. Editora has no capture hook, and its headless fixture writes a screenshot
  from three FX tests only, at the scene's own size too.
- **Docs links that open the running version's docs** ([DOCS-03](../../documentation/#docs-03)): Termina and Mirada
  each open their site's unversioned `/docs/`.
- **Toolbar groups separated by spacing, not lines** ([TBAR-04](../../toolbars-and-tooltips/#tbar-04)): the
  separators of Editora's Debug panel toolbar draw their line, and so do those of Torrenta's main toolbar.
- **A toggle that looks on while it is on** ([TBAR-07](../../toolbars-and-tooltips/#tbar-07)): Torrenta's palette
  button carries no pseudo-class while the palette shows.
- **A command that hides the tab bar** ([TABS-12](../../tabs-and-panels/#tabs-12)): the nearest Termina has is a
  setting, toggled from the palette, that hides the strip only while a window has one tab.

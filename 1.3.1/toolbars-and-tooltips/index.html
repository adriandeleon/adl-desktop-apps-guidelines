Toolbars and tooltips

A toolbar is the fast path to commands that are also in the menus and the Command Palette: nothing lives only on it. Every button is a command, so its icon, title and chord come from the registry and the active keymap. Reference: Editora’s ui/Icons.java (button, toolbarButton, name), ui/ToolbarCoordinator.java (the customizable bar), ui/WindowChromeCoordinator.java (collapseToolbarSeparators), ui/ToolWindowManager.java (the tool window stripes) and the .tool-bar, .toolbar-button, .tool-stripe-button and .tooltip rules in app.css.

  3. 3Tooltip. The command's title and its chord in the active keymap, "Save (C-x C-s)". A popup window with the menus' radius 8.
  4. 4Open toggle. A button whose overlay is showing (Find, the palette, a split) wears :open: an accent-subtle fill and the glyph in the accent color. Simple mode's own button does the same while the mode is on.
  5. 5One band. The menu bar, the toolbar and the tab strip sit on -color-bg-subtle with no hairline between them; spacing does the grouping.
  6. 6Pinned tail. The project picker, About and Quit live in their own container beside the ToolBar, so a narrow window overflows the icons (which are all in the menus too) and never the tail.

Rules

Section titled “Rules”
  • MUST. Every icon-only button has a name. Build it through one helper that sets the tooltip and the accessible text from the same string (Icons.button, Icons.name; Torrenta’s copy of both). A hand-rolled button gets the tooltip and forgets the name, which is how Editora once had seven copies of the helper drifting apart, and how a screen reader comes to announce “button”. nux sets both by hand on its ”?” button for the same reason.
  • MUST. Toolbar buttons stay out of the Tab order. Icons.toolbarButton sets focusTraversable to false: the command, the palette and the menus reach the action, and Tab is for the content. Termina’s search bar buttons do the same. The keyboard page has the general focus rules.
  • MUST. The tooltip names the command and its chord, read from the active keymap, never typed into a string: “Save (C-x C-s)”. Editora’s catalog buttons (ToolbarCoordinator), its stripe buttons (ToolWindowManager), Torrenta’s toolbar.withChord and Mirada’s header buttons all format it the same way.
  • SHOULD. Groups by spacing, not rules. Keep the Separator nodes (their padding is the gap) and make the line transparent. Hiding a button group (Simple mode, a build tool that is not detected) runs collapseToolbarSeparators, which hides leading, trailing and doubled separators so no gap is left standing on its own, and shows them all again when nothing is hidden.
  • SHOULD. One chrome band. The menu bar, the toolbar and the tab strip share -color-bg-subtle and draw no hairline between them; the breadcrumb, the bottom stripe and the status bar do the same at the bottom. Three rules within forty pixels read as clutter, not structure.
  • MUST. A toggle looks on while it is on. A button that opens an overlay (Find, the palette, a split) and the Simple mode button carry the :open pseudo-class while their state holds, so the way back out does not look like the way in. Torrenta uses :on for Simple mode and :active for the alternative speed limit.
  • MUST. The toolbar never holds the only way to an action. Every icon in the customizable cluster is also in the menus and the palette; that is what makes it safe to hide icons in a narrow window and to let the user remove them.
  • MAY. A customizable toolbar. Editora’s cluster is a list of catalog ids in Settings (toolbarLayout), sanitized on read and shared by every window. The bar’s right-click menu offers Customize Toolbar… (or Done), Configure… (the Settings page) and Restore Default. In customize mode the bar tints, buttons drag to reorder with an accent insertion line and drag off the bar to remove; Escape leaves the mode. Pinned by ToolbarCustomizeModeFxTest and ToolbarCustomizationFxTest.
  • The bar’s right-click menu is one menu, reused across right-clicks, so showing it again moves it, and ContextMenuDismissal closes it on a press anywhere, the toolbar included (ToolbarContextMenuDismissFxTest). The bar runs at 18 px, and a popup inherits the font of the node it was shown from; the .context-menu rule that pins menus to 14 px is what keeps this menu the size of every other (ToolbarMenuFontFxTest). See Menus.
  • Tool window stripes are toolbars. A stripe button is built like a toolbar button: tooltip with the chord, accessible text bound to the window’s title, a right-click menu with Open in Split and Hide. The right stripe’s first icon lines up with the editor’s first line of text, not with the tab strip (ToolWindowStripeAlignmentFxTest).

In the apps

Section titled “In the apps”
  • Editora: the customizable cluster, the pinned tail, the stripes.
  • Torrenta: the same Icons.toolbarButton and Icons.name, 32 px buttons, Simple mode as :on; its separators still draw a line.
  • Mirada: a HeaderBar title bar with flat icon buttons around the file name, stroked symbolic icons in the text color, tooltips of the form “label (chord)”; no accessible names on the buttons.
  • Termina: no main toolbar (its tabs are in the title bar); the search bar’s buttons are 24 × 22 flat icons with tooltips, out of the Tab order.

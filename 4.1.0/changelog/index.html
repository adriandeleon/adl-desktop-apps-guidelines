Edition

Changelog

Each edition of Pauta is a version, numbered as below. The entries come from the repository’s CHANGELOG.md, in Keep a Changelog form.

How editions are numbered

Section titled “How editions are numbered”

An edition is numbered major.minor.patch. The number says what moving an app to it costs, judged by the rules alone: which rules exist, their levels, and what each one asks. Only what the guide says moves it; how the site shows it never does.

  • Patch (4.1.0 → 4.1.1): an app built to the edition before it does nothing. The guide says the same thing more clearly or more correctly, and no rule’s ID, level or requirement changes: a rule reworded without changing what passes, a wrong fact about an app fixed (the matrix, Gaps per app, a Reference), a Check fixed to test what its rule already asked, a new or replaced screenshot, a page or section that adds no rule.
  • Minor (4.1.1 → 4.2.0): an app adds what the new or stronger rules ask, and undoes nothing. The rules change, but everything that conformed still conforms: a new rule at any level, a level raised (SHOULD → MUST, MAY → SHOULD) or lowered, a rule that covers more cases, a rule retired with nothing in its place.
  • Major (4.2.0 → 5.0.0): an app changes work it already did. Something that conformed must be undone or redone: a rule reversed, or replaced by one that asks for something else; a requirement changed so the old way now fails (a different file name, value, chord, color or layout); a change to what MUST, SHOULD, MAY or “built to an edition” means.
  • No edition: nothing a reader takes as guidance changes, so the number stays and the changelog has no entry. A typo or spelling fix, a broken link fixed or a link added, Markdown and markup, the site’s styles, scripts, build and branding, the PDF’s layout.

The largest change sets the number: an edition that adds ten rules and reverses one is a major. A new MUST is a minor, even when every app fails it today: an app names the edition it is built to (pauta.version, the About window), so a new MUST asks nothing of it until it moves, and moving adds work without undoing any. Numbers are never reused or changed, since every edition keeps its address; 2.0.0 and 3.0.0 were numbered under an earlier rule that made any new MUST apps failed a major, and under these rules both would be minors.

4.1.08 November 2026Read this edition

Added

  • Conformance. A new page under Start here says how an app implements Pauta: it names one edition and states its conformance, Complete (every MUST met, every SHOULD met or a recorded deviation), Core (every MUST met, some SHOULDs pending) or Partial (some MUSTs pending), and records every rule it does not meet as an exception in src/main/resources/com/<app>/pauta.json. An exception is not-applicable (with a reason), a deviation (SHOULDs only, with a decision record in docs/decisions/) or pending (with an issue). The conformance is computed from the exceptions by one tested helper, never stored; a PautaConformanceTest holds the file and the README to a copy of the edition’s rules.json; the app’s user docs get a Pauta conformance page with the same list; and a new app’s first release is Core or Complete. “Built to an edition” keeps its meaning, that the app meets its MUSTs: a Partial app says Working toward Pauta 4.1.0 instead. The page says “conformance”, not “level”, so “level” keeps meaning MUST, SHOULD or MAY. Rules PAUTA-01 to PAUTA-15.
  • Pauta window. A new template: a read-only panel built like About that shows the edition, the conformance and every exception, grouped pending, deviation, not applicable, with each rule linked in the app’s edition. It is the help.pauta command, so it is in the Command Palette, in the Help menu as Pauta Conformance just above About, and opened from About. Rules PWIN-01 to PWIN-08.
  • ABOUT-09. About shows the conformance after the edition: a Pauta conformance: Core link that opens the Pauta window, and a Pauta conformance: Core (2 exceptions) line after the Pauta: line. At Partial the edition’s link reads Working toward Pauta 4.1.0.

Changed

  • ABOUT-07 says that an app at Partial names the edition it is working toward. ABOUT-05 and ABOUT-06 are unchanged: the edition’s link and the Pauta: line stay as they were. WIN-07 names the conformance too.
  • Help menu. DOCS-07 puts Pauta Conformance between Report a Problem and About.
  • README badges. A Pauta badge after Platforms names the edition and conformance and links to the conformance docs page.
  • Auditing an app (Coding agents, llms.txt): a fifth step reads pauta.json, reports a listed rule by its kind, and treats an unlisted failure, a stale entry or a missing link as a finding. Move an app to a newer edition replaces the test copy of rules.json and updates pauta.json.
  • Checklist, matrix and gaps. A Conformance group on the checklist; a matrix row for the Pauta window and pauta.json; every app’s gaps list them.

4.0.28 November 2026Read this edition

Added

  • How editions are numbered. The Changelog page says what each part of the version means, judged by what moving an app to the edition costs. A patch asks nothing: wording, fixed facts, screenshots, pages without rules. A minor asks the app to add: a new rule at any level, a level raised or lowered, a rule retired. A major asks it to undo or redo work that conformed: a rule reversed or replaced, a requirement changed so the old way fails. A new MUST is a minor, even when every app fails it, so majors stay rare; 2.0.0 and 3.0.0 would be minors under these rules and keep their numbers. Typos, links, markup and the site’s look take no edition at all. Coding agents and LLMs says what each part means when an app moves to a newer edition. No rule changed.

3.0.07 November 2026Read this edition

Changed

  • Secrets and config safety are MUSTs. SET-11 (read a config file with suspicion: clamp on load, keep a file that can’t be read as a backup, never stop startup over it), SET-13 (no secret in a config file; keys and tokens in the OS keychain, off the FX thread), SET-14 (a credential the app can ask for again stays in memory), SET-15 (a secret in the wrong place is refused) and SET-16 (an option that weakens security has no UI) were SHOULDs and are now MUSTs, and the checklist lists them. Apps fail them today, so this is a major edition: Torrenta, Modula, Mirada and nux keep no backup of a bad config file, and in Torrenta and nux a malformed \uXXXX escape stops startup; Editora keeps its AI keys in settings.json as a fallback and writes the keychain on the FX thread, and lets plugin signature checking be switched off from Settings; Torrenta keeps its proxy, Torznab and remote-profile secrets in plain text. SET-11 now asks for a backup, not the exact name <name>.corrupt.bak, and its check includes a parser that throws something other than an IOException.
  • The checklist sets the level. Where a page and the checklist disagreed, the checklist wins, as AGENTS.md says: PLAT-04 (one JPMS module) is a MUST, which all six apps meet; TABS-15 (panel state restored), TBAR-07 (a toggle wears :open) and ICON-09 (readable text) are SHOULDs.
  • One rule for readable text. ICON-09 now holds what ICON-03 and KBD-19 repeated; those two IDs are retired, and Keyboard links to ICON-09.

Fixed

  • Follow the system. The feature matrix marked every app as following the system’s light or dark scheme; only Mirada and nux do. Editora, Torrenta, Termina and Modula switch live but have no system choice, and WIN-02 and ICON-16 name both apps that do.
  • Gaps per app lists what each app fails among the MUSTs above, and Editora’s row the MUSTs its rules’ References already said it misses.
  • SET-15 said a problem report redacts hosts; it redacts tokens, credentials, e-mail addresses, user names and home paths, and keeps the host.

2.0.06 November 2026Read this edition

Added

  • About names the Pauta edition. The About window now MUST show the edition of these guidelines the app implements: a Built to Pauta x.y.z link to that edition’s own address (https://pauta-project.dev/x.y.z/, not latest/) and a Pauta: x.y.z line in the environment block, so Copy details carries it. The number is the edition the app meets, not the newest, and comes from a pauta.version property in pom.xml read by AppInfo. No app does this yet; the matrix has a row for it and every app’s gaps list it. Window shell and the checklist say the same.
  • Coding agents can read the rules. Every edition serves rules.json (each rule’s ID, level, page, section, address, text, why, check and reference), llms-full.txt (every rule as Markdown in one file) and llms.txt (the index, which says how to audit an app: find the edition it names, take each rule’s check, report pass, fail, not applicable or manual with file:line evidence). The site root carries the latest llms.txt. Every link points at the numbered edition, so a citation never moves. The overview links them.
  • A malformed rule fails the build. npm run check fails on a rule head that doesn’t match, an ID used twice, a prefix on two pages, a rule without its Check or Reference line, or a table with a Level column; npm run build runs it first.

Changed

  • Every rule has an ID, a level and a check. 352 rules, from PLAT-01 to SYNC-02, each with a permanent anchor (#kbd-07), a level, a Check line (237 by reading the code, 80 by a named test, 35 by hand in the running app) and a Reference line naming the code. People and coding agents can audit an app rule by rule and cite what they find. Rule tables became lists, so a page has one shape for every rule; template pages keep their mockups and spec tables and open with a Rules section. The overview explains IDs once, and AGENTS.md lists each page’s prefix.
  • Levels. A rule that had a level keeps it. One that had none takes the checklist’s level, or SHOULD when the checklist doesn’t list it, so no app fails a new MUST. That makes MUSTs, among others, of the palette chord, overlay and command catalog keys, the Emacs and CUA keymaps, keymap layers, the icon-button helper, the FX test tag, the release supply-chain steps, --help / --version / --config-dir / --dev, single instance, the find bar’s Enter and Escape, the shared tray package, Settings search and live apply, and the six catalogs; and SHOULDs of --new-instance, --no-session and [files…], which the command-line page only listed.
  • Split and narrowed. Rules that held two requirements were split: keymap presets are now Emacs and CUA (MUST) and IntelliJ, VS Code and Sublime (SHOULD). Some rules were narrowed to what was meant: the rule against chords in translated text covers only command chords (Enter, Tab, Esc and a shell’s keys may be written), the Settings chord is CUA’s, an unknown theme falls back to the first-run default, a permission is write only where a job needs it, and an empty picker may say so in the status line instead. Tab reachability names toolbar buttons as the exception Toolbars and tooltips already makes.
  • Checked against the apps. Converting each rule meant checking it against the apps’ default branches, and the pages had facts wrong. Editora has 19 community themes, not 21; the window title’s unsaved marker is ●; the Redactor keeps hosts and drops e-mail addresses and credentials; the generated icons live in branding/; Editora’s release build uses Liberica; the Message Log is a card in OverlayHost, not a popup; Home and End move the caret in a picker and Ctrl/Cmd+Home/End jump rows; StatusSeverity reads fail or error in a status.* key’s last segment; the font classes are Fonts.BUNDLED and Fonts.loadForFirstPaint; adding a language also means listing it in Messages.LANGUAGES and MessagesTest.
  • Where Editora falls short. A rule Editora fails now says so in its Reference instead of claiming it passes: fixed hexes left in app.css, about twenty FX tests without the fx tag, an exit wait on the common pool, the main toolbar’s buttons without accessible text and in the Tab order, Shift+Enter in the editor’s find bar, no follow-the-system theme, no previous-tab command, settings without a palette command, and the uncaught-exception echo no app shows; Editora’s Universal Argument title still carries C-u.

  • Every repository document is a MUST except TODO.md: CONTRIBUTING.md, docs/ and branding/ join the rest. The matrix gains a CONTRIBUTING.md row and the gaps table lists who lacks it; Torrenta and Modula are marked for committing only CLAUDE.md, with no AGENTS.md.
  • The checklist is grouped by area, each group linking to its page, with a hanging indent for wrapped items.
  • The feature matrix fits on the page. Its page is wider and notes under a dot wrap, so all six columns show without scrolling sideways.

Tabs and tool panels

A window shows its documents in a tab strip and its tools in panels docked beside or under them. Both are driven by commands, both remember their state, and both draw their chrome as one band with the toolbar, not as boxes inside boxes. Reference: Editora’s ui/TabHeaders.java (the tab header), ui/ClosedTabs.java, ui/Switcher.java, ui/ToolWindowManager.java, ui/ToolWindowPanel.java and the .tab-pane, .tool-stripe and .tool-window rules in app.css.

  3. 3Pinned tab. A pin glyph and a bold title, kept at the front of the strip in pin order. Every bulk close (Others, All, Unmodified, Left, Right) skips it.
  4. 4Read-only tab. Muted and italic, echoing the status bar's Read-Only segment.
  5. 5Drag to reorder. The header is the drag handle and a snapshot of the whole tab follows the pointer; the dragged tab dims to 40 % and a 2 px accent line marks the edge it would land on (left half of a tab: before it; right half: after).
  6. 6Tool stripe. A 30 px rail of icon buttons, one per tool window, 8 px apart, on the subtle ground with no drawn edge. The open window's button is tinted; the one holding keyboard focus is tinted stronger. The first icon lines up with the editor's first line of text, not with the tab strip.
  7. 7Panel header. The window's glyph and title (14 px bold, muted) with float, maximize and close; the same size and glyph as its stripe button, so the two name the same thing. On the subtle ground, with no rule under it; when the panel holds focus the band tints accent-subtle and the title turns accent.
  8. 8The divider is the edge. The panel draws no frame: the SplitPane divider between it and the editor is the real, grabbable edge, and a hairline beside it would only double it. Its position is remembered.
  9. 9Bottom stripe. Its buttons carry a 14 px label beside the glyph, side by side; the open one is accent and bold.

Tabs

Section titled “Tabs”
  • MUST Every tab operation is a command, so it has a chord, a palette entry and a menu row: close, close others, close all, close unmodified, close to the left and right, pin, reopen closed, next and previous. The tab’s right-click menu lists them (TabContextMenu).
  • MUST. The header is the title. The Tab’s own text stays empty; a graphic header carries the file-type glyph, the markers and the title in a .tab-title label, which is what makes it a drag handle and lets each state set its own color (TabHeaders). The tooltip is the full path.
  • MUST. Bulk close skips pinned tabs. closeOtherTabs, closeAllTabs, closeUnmodifiedTabs and eligibleToLeft / eligibleToRight all filter on the pinned set; a pinned tab cannot be closed by accident. Pinning moves the tab to the end of the pinned group, unpinning to just after it (togglePin, moveToPinBoundary).
  • MUST. Reopen Closed Tab. ClosedTabs keeps the files whose tabs this window closed, newest first, bounded to twenty, a file listed once; reopening restores the caret. Termina brings back the tab (its shells, their directories, the pane arrangement, the names the user gave them, its place in the strip) and not the scrollback, because the process is gone and pretending otherwise would be worse than saying so. C-S-t in the CUA keymap; Termina Ctrl+Shift+Z, Cmd+Z on macOS.
  • Drag to reorder with the feedback above (TabHeaders.enableTabDrag; Termina installTabDrag and the pure TabReorder.insertIndex). In Termina a double-click on a tab renames it, and a pane dragged onto a tab joins it (the whole header outlined, tab-drop-into).
  • Git status on the tab in the Project tree’s colors: modified accent, added green, untracked olive, renamed violet, deleted muted, conflict red (TabGitStatus). A read-only tab still shows it; an unsaved one shows amber.
  • Switcher. C-x C-b (Emacs) opens an IntelliJ-style list of the open files in tab order: C-n / C-p or the arrows move, Enter or releasing Ctrl activates, C-g or Esc cancels, C-d or Backspace closes the highlighted file. Its width is fixed to the longest path on each open so it never resizes while you move (Switcher).
  • The window title names the file, the project and the app, with a • prefix for an unsaved file.
  • Tabs in the title bar SHOULD through JavaFX 27’s HeaderBar; see Window shell. The tab bar can be hidden by a command (view.toggleTabBar, .tab-pane.no-tab-header).

Tool panels

Section titled “Tool panels”
  • MUST. A command toggles each panel (tool.<id>: M-1 … M-0 in the Emacs keymap for ten of them), and the stripe button is the same command with a glyph. The panel’s content is built on first use.
  • MUST. State is restored. Which windows are open, on which side, in what order, hidden or shown, floating, and every divider position go to workspace-state.json and come back on the next launch (ToolWindowManager).
  • Three sides, two windows each. Left, right and bottom stripes (ToolWindow.Side); a side holds at most two windows stacked (Project over Structure, two consoles along the bottom), because “past that a side stops being a dock and becomes a list of slivers” (MAX_PER_SIDE).
  • Re-dock by dragging the stripe button to another stripe, with the same dim-and-accent-line feedback as a tab; an empty stripe appears as a dashed accent drop zone for the duration of the drag (ToolWindowDock).
  • Float, maximize, resize and close from the keyboard: view.maximizeToolWindow (C-x f), view.closeFocusedToolWindow (C-x 0), the resize commands (C-x S-., C-x S-,, C-x S-6). At most one window is maximized at a time.
  • Focus comes back. Closing the panel that holds keyboard focus returns it to where it was in the editor (focusEditor, a weak reference to the last editor focus owner).
  • Hidden is not unavailable. The user’s show/hide choice for a stripe button is kept apart from a context-driven hide (the Commit window outside a Git repository), so the second never clobbers the first (ToolWindowVisibility).
  • A bottom window that is unusable at the default height asks for more on its first open (setFirstOpenShare); the user’s own size wins afterwards. A stripe button badges a spinner while its window has something under way (busy).
  • Panels follow the active document where they should: the Git UI follows the active tab’s repository (GitPathScope), the status bar’s environment segment the active .http file, Local History the file whose tab menu opened it.

The other apps dock their panels the same way without a stripe. Torrenta’s filter sidebar sits down the left or the right of the list or nowhere, kept as two settings keys so hiding it keeps its side (SidebarPlace); its inner edge drags to resize within readable bounds and a double-click resets it (SidebarWidth); the detail pane docks under the list in two columns or beside it in one, from the View menu (DetailPane). Mirada’s info panel opens on the right and its thumbnail strip along the bottom or down the left side, each closed until its command asks for it (ThumbnailStrip.place). Termina splits a tab into panes instead: a pane is picked up with a drag while Ctrl+Alt+Shift (Cmd+Option+Shift on macOS) is held, since every smaller chord is spoken for (PaneDrag), and a maximized pane wears a “Pane 2 of 3” badge so the others are known to still be there.

Settings Sync

SHOULD in every app with user data worth carrying between computers (snippets, templates, shortcuts, profiles, saved views). A page in the Settings window, found by searching “sync”. No server and no account of ours: the store is a private Git repository the user owns, reached through their own Git credentials. Reference: Editora’s sync/ package (SyncEngine, SyncMerge, SyncAccount) and ui/SettingsSync.java, with the page in SettingsWindow; Torrenta and Termina carry the same package.

  1. 1Its own page in the Settings sidebar, under System, found by the Settings search ("sync", "git", "github").
  2. 2Repository URL. SSH or HTTPS. A URL with a password or token in it is refused, with the reason and the fix (a credential helper such as gh auth setup-git, or an SSH URL).
  3. 3Branch, Connect, Create on GitHub…. Connect clones or adopts the repository. Create on GitHub makes a private repository through the gh CLI and fills the URL in.
  4. 4Status pill plus Sync Now and Open Sync Folder (see the states below).
  5. 5What to sync: one switch per kind of data, each with a description when its scope is not obvious.
  6. 6What is not synced, said plainly: machine-local preferences, the keymap in use, anything with paths.
  7. 7Automatic sync with its interval in minutes (default 15, at least 1). Automatic runs never prompt.
  8. 8Privacy and conflicts, in one note: use a private repository; on a same-entry conflict the computer you sync from wins, and the other version stays in the history.

Green, amber and red are the Settings status-pill colours. Amber means “will recover by itself” (offline, the remote unreachable); red means “the user must act” (Git missing, the repository written by a newer version, a sync that would remove most of a kind of data and waits for confirmation). The pill’s accessible text is “Sync status: …”.

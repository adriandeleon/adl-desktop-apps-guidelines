About window

MUST in every app. Help → About, the help.about command, and on macOS the application menu’s About item. It answers “what exactly am I running?” in one place, and its details are what a bug report needs. Reference: Editora’s ui/AboutDialog.java; Torrenta (AboutDialog), Termina, Modula, Mirada and nux (AboutWindow) follow the same order.

  1. 1Identity. The app icon at 72 px beside the name (26 px, bold). No alert header band, no info graphic: the panel reads as one block, like a native About panel.
  2. 2Version and tagline. Version 14 px muted; a snapshot build appends its Git branch, "0.28.0-SNAPSHOT (feat/map)". The tagline is the README's one-line pitch, 13 px muted.
  3. 3Update status. What the last update check found (see the states below), when it ran, and Check now. Nothing is claimed before a check has answered.
  4. 4Copyright, muted.
  5. 5Links. Licence, homepage, source code and releases, and the settings file, which opens in the app (or in the file manager for apps with no editor).
  6. 6Environment. Monospace 11.5 px, muted: version and build time, commit, Java and JavaFX versions with vendor, OS with architecture, config folder. Home folders shown as ~.
  7. 7Copy details copies the environment block and stays open; its label becomes "Copied". It sits in the content, not the button bar, so pressing it does not close the panel.
  8. 8Close, the one button, and the default: Enter and Esc both close.

“Update available” links to that release’s page. An update check that is switched off must never read as “up to date”: with no answer, the panel says it has not checked.

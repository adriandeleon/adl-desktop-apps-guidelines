Gaps per app

The MUSTs each app still misses, then the SHOULDs open in several apps. Every row was read against an audit of the app’s MUSTs on 2026-11-10, at the head of the app’s default branch that day, and Editora’s against the rules that cite it. A part an app lacks is listed once, under the rule that requires it, and the rules about how that part behaves follow as links on the same clause: a missing find bar is FIND-01’s, and FIND-02, FIND-06 and FIND-07 follow it. Five rules say in their References that no app has been read through for them yet (OS-04, PERF-01, PERF-02, PERF-03, PERF-08): a row holds what was found so far, and a row with no clause for one of them is not a pass. A command id, catalog key, chord, command-line flag, environment variable, property in pom.xml or pauta.json, or file the repository must carry that a rule’s statement names is required as spelled; a class, method, style class, branch or workflow file there is Editora’s, and an app’s equivalent meets the rule (Coding agents).

Missing MUSTs

Section titled “Missing MUSTs”

Six MUSTs are open across the family. The rows leave OS-02, WIN-11, WIN-12 and ACC-01 out, and say for MENU-16 and CLI-12 what each app lacks. No app has the one Os class that alone reads os.name (OS-02): 51 files read it in Editora, 20 in Termina, 19 in Torrenta, 15 in Mirada, 4 in nux and 3 in Modula, and eight more of Editora’s tell Windows apart by File.separatorChar or File.pathSeparatorChar instead. No app fixes the order of a dialog’s buttons (WIN-11): none calls setButtonOrder, so Editora, Torrenta, Termina, Mirada and nux draw theirs in JavaFX’s order for the OS, and Modula’s one dialog has a single button. No app has a UI zoom (WIN-12): Editora, Termina and Mirada zoom their content only (the text, the terminal’s font, the image), and Torrenta, Modula and nux have no zoom. So no app’s menus follow one either (MENU-16): Editora’s and Mirada’s, the two that set the font on .context-menu, write 14 px as a fixed size. And no app meets all of CLI-12: the template comes nearest, and refuses a launcher’s JVM options with every other unknown one. And no app has the test that sweeps every window for a control with no name (ACC-01): Termina’s sweeps icon-only buttons, Editora’s and Mirada’s each check a few named sets of buttons, and Torrenta, Modula and nux have none. Editora’s in-window menu rows carry no accessible text; Torrenta sets one in a single helper, which names every button of its main toolbar and the Search view’s Clear button and not its ”···” button, and Modula sets none.

SHOULDs open in several apps

Section titled “SHOULDs open in several apps”
  • Windows .msi signing (REL-17): no app signs its MSI yet; the certificate isn’t chosen.
  • Settings in the macOS application menu (WIN-15): only Mirada puts it there, with a key equivalent of its own where the rule asks for the active keymap’s chord in the row’s title. Editora, Termina, Torrenta, Modula and nux have no such row.

  • The same short flags (CLI-13): Termina and Torrenta take -h, -v and -V. Editora has no -v and Mirada no short flags; Modula reads no arguments, and nux reads two long flags of its own, --minimized and --screenshot, and no short one.
  • One tooltip delay (TBAR-14): no app sets 400 ms on every tooltip. Termina sets it on its icon buttons and leaves its palette’s at JavaFX’s second; Editora sets 300 to 400 ms on a few, Mirada 250 ms on one, and the rest set none.

  • The config read begun before the toolkit (PERF-16): Editora starts it in main and start() takes the result.
